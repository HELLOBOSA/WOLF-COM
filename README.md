# WOLF-COM

Static site for wolfblanc.com. Plain HTML, CSS and JavaScript. No build step, no bundler,
no framework, no package manager. Served from GitHub Pages.

Planning and rules live in the `hellobosa/dna` repo. Read `dna/README.md` and
`dna/studio/voice.md` before writing any copy.

## Hard rules

- Push completed work to `main`. No feature branches, no pull requests, unless told
  otherwise for a specific task.
- No AI signatures, no "generated by" notes, no `Co-Authored-By` assistant lines. Not in
  files, not in commit messages, not in code comments.
- No em dashes anywhere. Search every file you touch before committing.
- Avoid AI writing tells in client-facing copy.
- Header and footer stay identical across every page.
- Do not add or change `CNAME` until domain wiring is explicitly approved.
- The live WordPress site is the content source of truth. Do not invent facts, figures,
  credentials or client names.

## Conventions

**Bilingual EN/ES.** Every user-visible string carries both attributes:

```html
<p data-en="Read article" data-es="Leer artículo">Read article</p>
```

`site-core.js` swaps `innerHTML` from the matching attribute on toggle and stores the
choice in `localStorage` under `wb-es-lang`. Elements with `aria-label` use
`data-en-aria` and `data-es-aria`.

An element with no `data-es` silently stays English forever. There is no warning. This has
already caused two shipped bugs. When adding any markup, add both attributes, then verify
by toggling.

**Theme.** Light and dark via a `wb-dark` class on `<html>`, stored under `wb-theme`.
Colours come from custom properties only. Never hardcode a colour:

```css
:root { --bg:#f4f1ea; --text:#0d0b0a; --text2:#6a655b;
        --accent:#94856a; --line:rgba(148,133,106,.14); --nav:rgba(245,240,235,.94) }
.wb-dark { --bg:#0d0b0a; --text:#f0ede7; --text2:#8f887c;
        --accent:#c3b087; --line:rgba(195,176,135,.14); --nav:rgba(13,11,10,.94) }
```

**Related cards.** Every studio, service and article page ends with a three-card strip
linking to siblings. Cards on one page must not repeat the same image.

```css
.rel-grid { display:grid; grid-template-columns:repeat(3,1fr);
            gap:1px; background:var(--line); border:1px solid var(--line) }
```

**Per-page CSS.** Each page carries its own `<style>` block plus the shared
`assets/site-shell.css`. Editing one page does not affect others. Editing a shared file
affects everything, so check breadth first.

## Gotchas

- **Image filenames contain spaces.** `images/Horizon House 01.webp`,
  `images/Casa Boadilla 01.webp`. Browsers encode these fine. Quote every shell path.
- **Every page is `noindex` until DNS cutover.** All 193 curated pages. Do not remove it
  page by page. It comes off in one sweep at launch.
- **The cookie banner is decorative.** GA4 (`G-WKLWDZFNKC`) loads unconditionally from
  `site-core.js`. Consent does not gate it. Fix before launch if that matters legally.
- **`wolfblanc.com` is unreachable from the agent sandbox.** Port 443 is proxy blocked.
  Use the `WOLFBLANC_ROYAL_MCP_C` MCP connector to read the live WordPress site.
- **Bulk edits are the norm.** Sitewide changes touch 100+ files. Write a Python script
  into the scratchpad, run it, then diff before committing. Do not hand-edit 98 footers.
- **Relative path depth.** Root pages use `../`, studio subpages use `../../`. Moving a
  page means rewriting every relative path, canonical, OG URL and JSON-LD breadcrumb in it.
