# WOLF-COM

Static site for wolfblanc.com. Plain HTML, CSS and JavaScript. No build step, no bundler,
no framework, no package manager. Served from GitHub Pages.

**Strategy, status, decisions and audits live in the `hellobosa/dna` repo, not here.**
Start with `dna/websites/projects/NETWORK-assessment-2026-07-30.md`, and read
`dna/studio/voice.md` before writing any copy. This file covers only what you need in
order to edit this repo without breaking it.

## Hard rules

- Push completed work to `main`.
- No AI signatures, no "generated by" notes, no `Co-Authored-By` lines. Not in files, not
  in commit messages, not in code comments.
- No em dashes anywhere. Check before every commit.
- Header and footer stay identical across every page.
- Do not invent facts, figures, credentials or client names.

## Layout

```
/                        homepage
/studio/                 hub + architects, culture, why-wolfblanc
/services/               14 service pages
/projects/               20 case studies plus hub
/locations/              9 city pages plus hub
/journal/                43 bilingual articles plus hub
/careers/ /contact/ /faq/ /legal/
/images/                 flat directory, /images/journal/ for article headers
/assets/                 site-shell.css, site-core.js, article-page.js, article.css
/scripts/                maintenance helpers
sitemap.xml  robots.txt  redirect-map.csv  REDIRECTS.md  CNAME
```

Root also holds about 1,000 redirect stubs and seven language directories
(`de/ el/ en/ es/ fr/ nl/ sv/`). They are not content. Ignore them unless working on
redirects. See `REDIRECTS.md`.

## Conventions

**Bilingual EN/ES.** Every user-visible string carries both attributes:

```html
<p data-en="Read article" data-es="Leer artículo">Read article</p>
```

`site-core.js` swaps `innerHTML` from the matching attribute and stores the choice in
`localStorage` under `wb-es-lang`. Elements with `aria-label` use `data-en-aria` and
`data-es-aria`.

**An element with no `data-es` silently stays English forever.** There is no warning. This
has caused several shipped bugs. Add both attributes, then verify by toggling.

Equally, `data-es` being *present* does not mean it is Spanish. Some values are copies of
the English. Check that the two values differ, not merely that both exist.

Anchors inside these attributes must use single-quoted hrefs, because the attribute itself
is double-quoted:

```html
<p data-en="see our <a href='../slug/'>guide</a>" data-es="ver nuestra <a href='../slug/'>guía</a>">
```

**Responsive images.** Every source image wider than 1000px has `-640w`, `-1024w` and
`-1600w` variants beside it. The original is never modified and stays in `srcset` as the
largest candidate, so high-density screens still receive full resolution. `sizes` values
come from measured render widths: the widest slot on the site is 1002px on desktop and
340px on mobile. Filenames containing spaces must be percent-encoded inside `srcset`,
because a raw space terminates a candidate.

**Analytics consent.** GA4 (`G-WKLWDZFNKC`) loads only after the visitor accepts. The gate
is in `site-core.js`; the banner markup is per page. Reject clears the analytics cookies.
Do not reintroduce an unconditional `loadAnalytics()`.

**hreflang.** 20 page groups carry a reciprocal four-language cluster with the three local
sites. If you rename or move any of those pages, the matching page on `.es`, `.gr` and
`.se` must change in the same pass, or the whole cluster is ignored. Journal articles are
deliberately excluded: they are original per site, not translations of each other.

**Theme.** Light and dark via a `wb-dark` class on `<html>`, stored under `wb-theme`.
Colours come from custom properties only. Never hardcode a colour.

**Per-page CSS.** Each page carries its own `<style>` block plus `assets/site-shell.css`.
Editing one page does not affect others. Editing a shared file affects everything.

**Related cards.** Every studio, service and article page ends with a three-card strip.
Cards on one page must not repeat the same image.

## Gotchas

- **Image filenames contain spaces.** `images/Horizon House 01.webp`. Quote every shell
  path, and percent-encode in `srcset`.
- **Indexing is selective.** The URLs in `sitemap.xml` are `index, follow`. Redirect stubs,
  helper pages and the 404 stay `noindex`. Never rewrite robots metadata across every file.
- **Bulk edits are the norm.** Sitewide changes touch 100+ files. Write a script into a
  scratchpad, dry-run it, diff, then commit. Do not hand-edit 98 footers.
- **Relative path depth.** Root pages use `../`, studio and journal subpages use `../../`.
  Moving a page means rewriting every relative path, canonical, OG URL and JSON-LD
  reference in it.
- **The homepage gallery is built in JavaScript** from a `PROJECTS` array. A sitewide
  markup change that rewrites `<img>` tags with a regex will silently miss it.
- **JSON-LD `@id` references can dangle.** A block can be valid JSON and still point at an
  id that exists nowhere. Check resolution, not just validity.
- **Spanish accents** matter: `Años` not `Anos`, `Países` not `Paises`, `-ción` not `-cion`.

## Verify in a browser, not with a regex

Static scanning of this repo has produced false confidence repeatedly, in both directions.

The regex `<(h1|h2|h3|h4|p|li)` has no word boundary, so `<link>` parsed as `li` and
swallowed whole page heroes. Sweeps reported clean coverage while heroes shipped in
English.

Two more recent cases, both false alarms rather than misses. `naturalWidth` on an image
using a `w`-descriptor `srcset` returns the density-corrected value, not the file's real
width, so a 1024px file in a 351px slot reports as 351 and looks like under-serving when it
is the opposite. And an image with `loading="lazy"` first in source order is not
necessarily above the fold: on the homepage it sits 1,499px down, where lazy is correct.

The reliable check is to render it:

```bash
python3 -m http.server 8765          # serve the repo
# then in Playwright: load the page, click [data-lang-switch="es"],
# diff document.body text before and after. Anything identical is untranslated.
```

`scripts/article-i18n.py` is the tool for article translation work: `extract <slug>` dumps
untranslated blocks as TSV, `apply <slug> <tsv>` writes the Spanish back, `status` reports
progress.
